文件一：從 0 到 1 打造你的專屬 AI 助手 (Open WebUI 桌面版操作指南)

這是一份為初學者量身打造的實戰手冊。我們將使用「Open WebUI 桌面版」，在完全不寫程式碼的情況下，建立你的專屬 AI（例如：UI/UX 顧問）。

📸 [建議配圖：Open WebUI 桌面版乾淨的首頁截圖]

第一階段：下載與安裝

  1. 取得安裝檔：
    • 打開瀏覽器，前往官方下載頁面：https://github.com/open-webui/desktop/releases
    • 往下滑動找到 Assets 列表，點擊下載對應你系統的檔案（Windows 請點擊結尾為 .exe 的檔案，如 open-webui-setup-x64.exe）。
  2. 執行安裝：
    • 雙擊下載好的 .exe 檔案，一路點擊「下一步 (Next)」直到安裝完成。
  3. 首次啟動與帳號建立：
    • 在桌面雙擊「Open WebUI」圖示開啟軟體。
    • 畫面會彈出「設定您的環境」，請保持預設，直接點擊黑色的 「繼續」。
⚠️ 帳號與密碼輸入注意：
首次進入系統會要求你「註冊 (Sign Up)」建立管理員帳號。請在此處輸入你自訂的名稱、Email 與密碼。請放心：這個帳號密碼僅存放在你這台電腦的本機端，不會連上外網，隨便填寫也能通過。

第二階段：建立與調整你的專屬 AI 模型

我們要在系統中建立一個全新的「角色大腦」。

📸 [建議配圖：Workspace (工作區) 新增模型的設定畫面]
  1. 進入工作區： 點擊畫面左側選單的 Workspace（工作區）。
  2. 新增模型： 點擊頂部的 Models（模型） 標籤，然後點擊右上角的 + Create a Model（建立模型）。
  3. 設定模型屬性（這就是調整的核心）：
    • Name (名稱)： 輸入你的 AI 名字，例如 UI/UX 設計顧問。
    • Base Model (底層模型)： 點擊下拉選單，選擇 Ollama 已經下載好的模型（例如 llama3）。
    • System Prompt (系統提示詞)： 這是 AI 的靈魂。請將你要賦予它的規則貼在這裡，例如：
      > 你是一位資深 UI/UX 設計師。請針對我提出的介面需求，提供關於操作流程 (UX) 與排版配色 (UI) 的具體建議。
  4. 儲存： 點擊右下角的 Save & Create（儲存並建立）。

第三階段：存取海量資料（知識庫 RAG）

如果你的 AI 需要參考長達數百頁的年度文件、PDF 或是設計規範，不能塞進 Prompt，必須用知識庫存取。

  1. 建立知識庫： 點擊左側選單的 Workspace ➔ Knowledge（知識庫） ➔ 右上角的 +。
  2. 上傳文件： 命名知識庫（例如 年度設計規範），然後將你的 PDF/TXT 檔案直接拖曳進去，點擊儲存。
  3. 綁定模型： 回到 Models 頁面，點擊你剛才建立的 UI/UX 設計顧問 旁邊的編輯按鈕（鉛筆圖示）。往下捲動找到 Knowledge 區塊，勾選 年度設計規範，最後點擊儲存。

第四階段：日常對話與手動刪除/管理

  • 開始對話： 點擊左上角的 + (新對話)，在畫面正上方頂部的下拉選單中，選擇 UI/UX 設計顧問，即可開始發問。
  • 手動修改 (Edit)： 如果覺得 AI 語氣不對，回到 Workspace ➔ Models，點擊該模型旁邊的「鉛筆圖示」，就能隨時修改 System Prompt。
  • 手動刪除 (Delete)： 如果不需要這個助手了，在 Workspace ➔ Models 列表中，點擊該模型最右側的「垃圾桶圖示」，即可將其徹底刪除（這不會刪除底層的 Llama 3 模型，只會刪除這個角色設定）。

文件二：破解迷思！LLM 運作原理與 API 呼叫全解析

這份文件將由淺入深，直接破除你之前的觀念誤區，還原 AI 在你電腦中真正的運作架構。

📸 [建議配圖：簡單的流程圖，顯示 網站 -> Ollama -> 回傳結果]

第一章：你的三大誤解與真相破解

❌ 誤解一：Open WebUI 是幫我處理 API 與轉發資料的核心系統。

✅ 真相：Open WebUI 只是個「展示間（試衣鏡）」。
它是為了讓你不寫程式碼就能用滑鼠點擊、測試 AI 而存在的。當你要開發自己的網站或 App 時，Open WebUI 完全可以關閉，它並不參與正式的 API 資料轉發。

❌ 誤解二：我在 Open WebUI 寫好的 Prompt，會自動存進 Ollama 裡。

✅ 真相：兩者的資料庫是獨立的。
你在 Open WebUI 寫的「UI/UX 顧問設定」，只存在 Open WebUI 的沙盒裡。Ollama 底層本身依然是一張白紙（純潔的 Llama 3）。

❌ 誤解三：我的網站 ➔ 呼叫 Ollama ➔ Ollama 去 Open WebUI 找設定 ➔ 回傳。

✅ 真相：你的網站 ➔ 帶著設定直接呼叫 Ollama ➔ Ollama 運算後直接回傳。
正式運作時，資料流向是「直線」的，完全沒有 Open WebUI 的戲份。

第二章：LLM 真正的運作與呼叫架構

要讓你的網站或程式呼叫 AI，系統必須分工明確：

  1. 「引擎」：Ollama
    • 職責： 負責啟動顯示卡與 CPU 進行暴力運算。
    • 狀態： 必須長開。它預設會在你的電腦上開啟一個 API 門牌號碼：http://localhost:11434。
  2. 「大腦白紙」：底層模型 (Base Model)
    • 例如 Llama 3、Qwen。它們懂很多知識，但沒有特定性格。
  3. 「店面」：你寫的程式 / 網站
    • 職責： 把使用者的問題，加上你規定好的「角色設定 (Prompt)」，打包成一個包裹，直接丟給 Ollama 算答案。

第三章：如何將「沙盒」成果變成「正式 API 呼叫」？

你在 Open WebUI 測試出一套完美的 Prompt 後，有兩種方法可以讓你的程式呼叫它：

方法 A：由你的程式碼主動帶入規則 (最常用)

把你在 Open WebUI 寫的設定，直接寫進你的程式碼裡發送給 Ollama。

// 這是一段完整的 JavaScript 呼叫 API 範例
fetch('http://localhost:11434/api/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    model: 'llama3', 
    messages: [
      // 將你測試好的 Prompt 放在這裡
      { role: 'system', content: '你是一位資深 UI/UX 設計師，請針對操作流程給出專業建議。' },
      { role: 'user', content: '幫我評估這個登入畫面的排版好不好？' }
    ]
  })
});

方法 B：將規則「烙印」進 Ollama，變成一個新實體 (Modelfile)

如果你不想每次在程式碼裡重寫一大串規則，你可以用終端機強行在 Ollama 裡創造一個新模型。

步驟 1：在電腦隨便一個地方建立一個純文字檔，命名為 Modelfile（不需要副檔名），貼入完整程式碼：

# 1. 繼承底層模型
FROM llama3

# 2. 烙印你的專屬規則
SYSTEM """
你是一位資深 UI/UX 設計師。請針對操作流程 (UX) 與排版配色 (UI) 提供具體建議。
"""

步驟 2：打開電腦的 Terminal (終端機/命令提示字元)，輸入以下完整指令執行編譯：

ollama create my-uiux-agent -f ./Modelfile

步驟 3：用 API 呼叫新模型

現在，Ollama 的資料庫裡真正有這個模型了！你的網站以後發送 API 時，不用再傳送一長串 System Prompt，只要直接指定模型名稱即可：

// 你的網站後端程式碼
fetch('http://localhost:11434/api/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    model: 'my-uiux-agent', // 直接呼叫你剛才烙印好的新實體
    messages: [
      { role: 'user', content: '幫我評估這個登入畫面的排版好不好？' }
    ]
  })
});
